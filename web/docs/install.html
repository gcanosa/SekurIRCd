install

SekurIRCd builds from source with a C11 compiler and make. It runs on macOS, Linux and the BSDs.

dependencies

  • A C11 compiler (clang or gcc) and make.
  • OpenSSL 3 (or LibreSSL) headers and libraries, used for scrypt hashing, randomness and TLS. macOS: brew install openssl@3. Debian/Ubuntu: apt install libssl-dev.
  • Everything else (tomlc99, cJSON, uthash/utlist) is vendored in src/vendor/.

build

git clone https://github.com/gcanosa/SekurIRCd.git
cd SekurIRCd
make            # release build -> bin/sekurircd, bin/chanserv
make debug      # ASan+UBSan build -> bin/sekurircd-debug
make check      # build and run tests/unit.c
make clean

run

cp config/sekurircd.template.toml config/sekurircd.toml
# edit config/sekurircd.toml (port, operators, TLS, ...)
./bin/sekurircd --config config/sekurircd.toml    # listens on 0.0.0.0:6667 by default

./bin/sekurircd --hash-password    # prompts, no echo, prints an scrypt hash for [[operators]]
./bin/sekurircd --version

Smoke test from another terminal:

nc 127.0.0.1 6667
NICK test
USER test 0 * :Test User
JOIN #general
PRIVMSG #general :hello
QUIT

start/stop/status script

The repo root ships a small wrapper, ./sekurircd, that runs both daemons in the background with the right flags and pidfiles, so you don't manage them by hand:

./sekurircd start     # sekurircd, plus chanserv if services/services.toml exists
./sekurircd status    # running/stopped for each, with pid
./sekurircd stop      # stops chanserv first, then sekurircd (graceful)

It always works from the repo directory, using config/sekurircd.toml, services/services.toml and the pidfiles sekurircd.pid and services/chanserv.pid. It refuses to start if bin/ isn't built yet, ChanServ is skipped when it isn't configured, and starting an already-running daemon is refused rather than duplicated. If status finds a matching process but no valid pidfile, it says so instead of reporting "stopped". There is no restart subcommand: run ./sekurircd stop && ./sekurircd start, or ./bin/sekurircd --rehash to reload the config without restarting.

daemon mode

./bin/sekurircd --config config/sekurircd.toml --daemon --pidfile /var/run/sekurircd.pid
./bin/sekurircd --stop   --pidfile /var/run/sekurircd.pid   # graceful stop, removes the pidfile
./bin/sekurircd --rehash --pidfile /var/run/sekurircd.pid   # reload config live (SIGHUP)

Without --pidfile the default is ./sekurircd.pid (or $SEKURIRCD_PIDFILE). Once daemonized, stdout and stderr go to /dev/null, so enable [logging] in the config.

systemd user service

make install sets both daemons up as systemd user units (Linux only). Nothing needs root: everything installs under $HOME, and the default ports (6667/6697) are above 1024.

make
make install
#  binaries         -> ~/.local/bin
#  config templates -> ~/.config/sekurircd   (never overwrites a live sekurircd.toml)
#  state and logs   -> ~/.local/state/sekurircd/{ircd,chanserv}
#  units            -> ~/.config/systemd/user

cp ~/.config/sekurircd/sekurircd.template.toml ~/.config/sekurircd/sekurircd.toml
systemctl --user enable --now sekurircd
systemctl --user reload sekurircd      # same as --rehash
journalctl --user -u sekurircd -f

A user unit stops when your last session ends. To keep it running after logout or start it at boot: loginctl enable-linger $(whoami). make uninstall removes binaries and units but leaves your config and state. Override PREFIX, SYSCONFDIR, STATEDIR or UNITDIR on the make command line to relocate any of it.
