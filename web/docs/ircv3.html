IRCv3 & SASL

capabilities

history

[messages]
history_size = 50                # messages kept per conversation; 0 turns history off, max 500
#history_file = "history.json"   # survive restarts (history and read markers)
#history_dm = true               # also keep private messages between two logged-in accounts

Clients with draft/chathistory and batch ask for what they missed. Replies come in a BATCH of type chathistory, each message with its original time and msgid tags.

CommandReturns
CHATHISTORY LATEST <target> * <limit>The newest messages. With a timestamp= or msgid= instead of *, only those newer than it.
CHATHISTORY BEFORE|AFTER|AROUND <target> <ref> <limit>Messages before, after or around a reference (timestamp=2026-10-09T17:20:43.123Z or msgid=...).
CHATHISTORY BETWEEN <target> <ref> <ref> <limit>Messages between two references, in either order.
CHATHISTORY TARGETS <ts> <ts> <limit>Your channels and private chats with activity in that window, newest first.

A channel's history is readable by its members (and IRC operators) and is kept even when the channel empties. Private history needs both sides to be logged in to an account. Requests are capped at 100 messages.

With draft/read-marker, a logged-in client sends MARKREAD <target> timestamp=<time> as you read. The server keeps the latest position per account and target, sends it on JOIN, and forwards every change to your other sessions, so a conversation you read on one device shows as read on the others. MARKREAD <target> without a timestamp asks for the stored one.

accounts

[accounts]
enabled    = true
store_file = "accounts.json"

Ways to register, all creating the same account and logging you in at once:

MethodCommand
NickServ/msg NickServ REGISTER <password> [email]. The account is named after your current nick.
IRCv3 draftREGISTER <account|*> <email|*> <password>. * means your nick. Replies REGISTER SUCCESS. The email is accepted but not stored or verified. Not available before the connection is registered.
Classic/REGISTER <account> <password>

To log in later: /msg NickServ IDENTIFY [account] <password> (account defaults to your nick). The best way is SASL, below, which logs you in during connection so no IDENTIFY is needed. NickServ here is built in: it answers only when no real user or service is called NickServ, and does not appear in /WHOIS. Accounts back 330 RPL_WHOISACCOUNT and the extban a:<account> for +b, +e and +I, matching by account instead of hostmask. The store is independent of ChanServ.

SASL PLAIN

Configure your client for SASL PLAIN with your account name and password. It sends AUTHENTICATE PLAIN during connection setup. PLAIN sends the password itself, so use it only over TLS.

SASL SCRAM-SHA-256

SCRAM proves you know the password without sending it, and the server proves it knows it too, so a fake server cannot collect passwords. The server stores only a salted SCRAM key derived from the password, never the password.

The key is made when the account is registered or when you log in with a password (PLAIN or IDENTIFY). An older account that has never done either has no key yet, and SCRAM fails for it once: log in with PLAIN one time, then SCRAM works. Changing the password replaces the key. The SekurNet web chat uses SCRAM automatically and falls back to PLAIN only in that one case.

SASL EXTERNAL (certificate login)

EXTERNAL logs in with a TLS client certificate instead of a password. The server does not validate the certificate against a CA; it only checks whether that exact SHA-256 fingerprint is bound to an account, so self-signed is fine.

1. ask for client certificates

[tls]
enabled = true
request_client_cert = true   # only requests a cert; clients without one still connect

2. make a certificate

openssl req -x509 -newkey rsa:2048 -nodes -days 3650 \
  -keyout client-key.pem -out client-cert.pem -subj "/CN=myaccount"

Most clients (WeeChat, irssi, ...) have a "client certificate" option pointing at the pair.

3. bind it to your account

Connect with the certificate, log in normally (PLAIN or /REGISTER), then:

/CERT ADD      # binds the fingerprint of the certificate you connected with
/CERT INFO     # show it
/CERT DEL      # remove it (disables EXTERNAL until you ADD again)

4. connect passwordless

Connecting with that certificate and sending AUTHENTICATE EXTERNAL logs the account in. Most clients do this automatically once both client-cert and SASL EXTERNAL are configured.
