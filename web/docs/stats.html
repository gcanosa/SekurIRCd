stats panel

The stats panel is a web page for the people who run the network. It answers the questions an IRC admin asks every day: is everything linked, how many people are on, when did that leaf split and why, are services up, is the protection layer catching anything, and will a certificate expire soon. It keeps the history, so you can also see last week or last year.

It is optional and off by default. Nothing is collected, written or served until you turn it on, and it needs no extra software: stats/netstats.py is plain Python (3.11 or newer, standard library only) and stores its history in SQLite.

how it works

There is no extra bot on your network and nothing to install on the leaves.

  1. The hub already knows the whole network. When services ask (a SVCSTATS request over their link), it sends a snapshot (users, channels, every server and its uplink) and, from then on, every link, split (with its reason) and ban as it happens.
  2. Every server sends its own numbers (CPU, memory, version, DNSBL, proxy scanner, spam filter) every stats_interval seconds, network-wide, as the stats line in the debug channel. The hub passes those on too.
  3. Services (bin/services, next to the hub) write all of it to stats/events.log: a snapshot every minute, events as they come.
  4. netstats loads that log every minute into stats/stats.db, probes the servers from outside, and shows the result.

Since services run once per network, next to the hub, the panel runs there too. A leaf only needs stats_interval.

History is kept per minute for 7 days, per hour for 90 days and per day for retention_days (365 by default), so the database stays small.

turning it on

The quickest way is to answer yes in the config generator (sekurircd --makeconf or tools/makeconf.py), or tick it in the web wizard. It writes stats/stats.toml with your admin login and sets stats_interval. By hand, on the hub:

./sekurircd enable-stats                          # writes stats/stats.toml from the template, collector on
stats/netstats.py --user --admin --add yourname   # a login for the panel (asks for its password)
./sekurircd start-stats                           # http://127.0.0.1:8089/admin/

Services notice stats/stats.toml within 30 seconds; nothing needs a restart and nobody is disconnected. Then, on every server (hub and leaves), for CPU, memory, version, the protection numbers and the heatmap:

[debug_channel]
enabled = false            # the channel itself is optional
stats_interval = 300

Apply that with /REHASH.

day to day

CommandWhat it does
./sekurircd start-stats / stop-stats / restart-statsThe panel alone. ./sekurircd start, stop and restart include it.
./sekurircd statusShows netstats: running (pid N), stopped or disabled.
./sekurircd disable-statsEverything off: stops the panel and renames stats.toml to stats.toml.disabled, so services stop collecting. History and logins are kept.
./sekurircd enable-statsBack on, exactly as it was.

The panel logs to logs/netstats.log. With systemd, systemctl --user enable --now netstats runs it instead of the wrapper (see install).

logins

There are two kinds of login. An admin sees everything. A viewer sees the same page without the Security section and without server IP addresses.

stats/netstats.py --user --admin --add alice     # asks for the password
stats/netstats.py --user --viewer --add staff
stats/netstats.py --user --status                # lists them
stats/netstats.py --user --viewer --del staff
stats/netstats.py --mkpasswd                     # just print a hash, for a [[users]] entry written by hand

They edit the [[users]] entries in stats/stats.toml (passwords are stored as scrypt hashes, like operator passwords) and the running panel picks the change up at once. After 10 wrong passwords in 10 minutes, an address has to wait.

The logged-in page is at /admin/. The page at / asks for a login too, unless you set public = true: then anyone gets the viewer page there, with a Log in link for the rest.

putting it online

By default the panel listens on 127.0.0.1:8089 only. To reach it from outside, either:

  • use a reverse proxy (recommended) that already serves your website with HTTPS: 
    # nginx
location /stats/ {
    proxy_pass http://127.0.0.1:8089/;
    proxy_set_header Authorization $http_authorization;
}
  • or let it serve HTTPS itself: set bind = "0.0.0.0" and point tls_cert/tls_key at a certificate (the ircd's works, for example "../config/tls/cert.pem"), and open the port in your firewall (below).
  • or just look at it over SSH: ssh -L 8089:127.0.0.1:8089 yourhub, then open http://127.0.0.1:8089/admin/.

the port and the firewall

The port is port under [http] in stats/stats.toml (8089 by default; makeconf and the wizard ask for it). After changing it, ./sekurircd restart-stats.

With bind = "127.0.0.1" (the default) the firewall needs nothing: only the reverse proxy or your SSH tunnel talk to the panel. With any other address, nobody can reach the panel until the port is open in the server's firewall. Use the one your system runs (replace 8089 with your port):

sudo ufw allow 8089/tcp                                   # Ubuntu, Debian with ufw
sudo firewall-cmd --permanent --add-port=8089/tcp         # Fedora, RHEL, Rocky, Alma
sudo firewall-cmd --reload
sudo iptables -I INPUT -p tcp --dport 8089 -j ACCEPT      # plain iptables
sudo netfilter-persistent save                            #   ...kept across reboots
# pf (FreeBSD, OpenBSD, macOS): add to /etc/pf.conf, then: sudo pfctl -f /etc/pf.conf
pass in proto tcp to port 8089

Cloud servers (AWS, Hetzner, OVH, DigitalOcean, ...) often have a second firewall in the provider's control panel (a "security group" or "cloud firewall"): open the port there too. When the panel starts bound publicly, ./sekurircd start-stats, netstats.py check and logs/netstats.log print these same commands with your port.

Without tls_cert, a public panel sends its logins in clear text (HTTP Basic auth), and netstats warns about it. Use HTTPS, or keep 127.0.0.1 behind a reverse proxy that has it.

static pages for a website

If you'd rather not run a web server at all, set [http] enabled = false and the paths under [export], and run netstats.py render from cron. It writes a viewer page (public_html) and an admin page (admin_html, protect it with your web server); each is a single self-contained HTML file.

*/5 * * * *  cd /home/irc/SekurIRCd && python3 stats/netstats.py render

the map

The map is built into the page (Natural Earth, public domain), so it works without any outside request. Each server is placed by its address:

  • run stats/netstats.py geoip-update once a month to download the free DB-IP Lite city database (CC BY 4.0). Lookups are made locally: no server address is ever sent anywhere.
  • or place a server yourself, which also fixes a wrong guess: 
    [[servers]]
name = "irc.example.net"     # as in /LINKS
location = "Amsterdam, NL"
lat = 52.37
lon = 4.90

The same [[servers]] entry can set host (what to probe and locate, when the server name doesn't resolve), ports (which ports the health checks try) and hide = true (leave it off the page).

configuration

stats/stats.toml, with every option explained in stats.template.toml:

SectionWhat it sets
[collector]enabled (services collect), sample_seconds (snapshot interval, 60), log.
[storage]database, retention_days (7 to 3650).
[http]enabled, network_name, bind, port, tls_cert, tls_key, public.
[export]public_html, admin_html: what render writes.
[geoip]file: the DB-IP database geoip-update downloads.
[health]ports, tls_ports, interval, timeout.
[[users]], [[servers]]Logins (managed with --user) and per-server overrides.

tools/confcheck.py checks this file along with the others, tools/backup-config.sh backs it up with the database, and tools/upgrade.py keeps both and restarts the panel after an upgrade.
