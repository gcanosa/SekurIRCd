configuration

Copy config/sekurircd.template.toml to a live file and point the daemon at it with --config. The template documents every key. REHASH (or --rehash) reloads it without dropping anyone.

Relative paths: motd, oper_motd, rules, tls.cert_file and tls.key_file resolve against the config file's directory; logging.directory resolves against the current working directory. Absolute paths always work.

Full templates on GitHub: config/sekurircd.template.toml (ircd) and services/services.template.toml (ChanServ). Every key is listed there with its default and a comment.

tls

[tls]
enabled   = true
port      = 6697
cert_file = "tls/cert.pem"
key_file  = "tls/key.pem"

A self-signed certificate still encrypts the connection. Clients just need "only allow trusted certificates" unchecked. Channel mode +z then restricts a channel to clients connected this way.

a real certificate (optional)

If you own a domain pointing at your server and want clients to connect without any trust warning, tools/mkcert.sh gets a free, trusted Let's Encrypt certificate, drops it where [tls] expects it, enables [tls] if it wasn't, sets up automatic renewal, and rehashes the running ircd so the new certificate is used without a restart. It is also what browsers need for the web chat over wss://. Skip it if a self-signed certificate is fine for you.

export DuckDNS_Token=your-token     # or prompted; any acme.sh DNS plugin works via --dns
tools/mkcert.sh --domain irc.example.org --email you@example.org
tools/mkcert.sh --domain irc.example.org --staging    # test run with untrusted certs
tools/mkcert.sh --domain irc.example.org --dry-run    # show what would happen

It installs acme.sh if missing and proves domain ownership with a DNS-01 challenge (a temporary TXT record), so port 80 doesn't need to be open. The default plugin is DuckDNS; pick another with --dns dns_cf etc. and export that plugin's credentials, or use --webroot DIR for HTTP-01 instead. Old certificate files are kept as *.bak. Other options: --domain (repeatable), --config, --pidfile. For web chat it also reminds you to set [websocket] with tls = true if it isn't.

operators

An [[operators]] entry is a /OPER login: name, hosts (ident@IP masks it may log in from) and exactly one of password_hash (scrypt, recommended) or a legacy plain password.

./bin/sekurircd --hash-password
# -> scrypt$16384$8$1$3f9c1a7b2e8d4f56...$91ab...   (example, truncated)
[[operators]]
name = "admin"
password_hash = "scrypt$16384$8$1$<salt-hex>$<digest-hex>"   # from the step above
hosts = ["*@*"]                                       # or restrict, e.g. ["*@203.0.113.42"]

Already have plain-text passwords in the file? tools/confcheck.py --fix --write turns every one the server can check as a hash (operators, die_password/restart_password, link peers it only accepts from) into a password_hash: the same passwords keep working. The ircd logs a reminder at start and on every /REHASH while any are left. The backup it makes still holds the old passwords, so delete it once /OPER works.

Apply it with /REHASH from an already-opered client, sekurircd --rehash, or a restart, then confirm with /OPER admin <password>. Rotating a password is the same edit in place. Removing an entry does not deop clients that are already opered under it until they reconnect.

An optional privileges list limits which oper commands a login may use (without it, everything is allowed): kill, kline (KLINE/GLINE/ZLINE, SPAMFILTER, PROTECT), sa (SAJOIN/SAPART/SAMODE/SANICK), host (CHGHOST/SETHOST/CHGIDENT/USERIP), wallops, rehash, die, link (SQUIT/CONNECT) and all. NickServ SUSPEND/UNSUSPEND/FDROP/SASET are for services admins ([nickserv] admins, by account), not an oper privilege. privileges = [] makes a helper oper with none of them.

server links

Servers link into a tree. One server listens ([links] port, a single port for every server that dials in: each one is told apart by the name it sends, not by port); the others dial it with host/port in their peer entry. tools/linkmgmt.py add asks a few questions and prints the blocks for both servers, plus the firewall and restart steps; tools/linkmgmt.py test HOST PORT --tls checks DNS, the port and TLS from either side.

Encrypt and pin: set [links] tls = true on both servers (the listening one needs [tls] enabled; its certificate is reused) and put the other server's certificate fingerprint in each peer entry. tools/linkmgmt.py fingerprint prints a server's own.

# on the hub: the leaf that dials in
[[links.peers]]
name = "irc2.example.net"
password_hash = "scrypt$16384$8$1$<salt-hex>$<digest-hex>"   # optional once a fingerprint is set
fingerprint = "sha256:<the leaf's certificate>"
allowed_ips = ["203.0.113.7"]

# on the leaf: the hub it dials
[[links.peers]]
name = "irc1.example.net"
password = "the-shared-secret"                                 # optional once a fingerprint is set
host = "irc1.example.net"
port = 17000
fingerprint = "sha256:<the hub's certificate>"

With a fingerprint, a self-signed certificate is enough (no CA and no tls_insecure_skip_verify), and a server that doesn't show the pinned certificate is refused before any password is sent or checked. Leave both password keys out and the certificate alone authenticates the link, so neither server keeps a plain-text secret. After renewing a certificate with a new key, update the fingerprint on the other side and /REHASH. The services daemon doesn't speak TLS: a TLS link listener still accepts plain links from 127.0.0.1 for it, and only TLS from anywhere else.

The port: anything free works; a number outside the 6660–7000 range that IRC scanners probe (and below 32768, the system's outgoing-port range), e.g. 17000, cuts the noise. What actually protects it is a firewall rule that only lets your servers in, allowed_ips on each peer, and the pinned TLS above, or [links] bind on a private network address (WireGuard, your provider's private network) so it isn't public at all. Changing the port needs a restart of the listening server.

file permissions

sekurircd.toml, services.toml, the TLS key, accounts.json and the ChanServ store hold secrets. tools/confcheck.py warns about any of them other local users can read or change, and prints the exact fix for each: chmod 600 for your own files, sudo when another user owns one, or chown to the daemon's user (or 640 through its group) when it runs as someone else, so the daemon isn't locked out.

host cloaking

[security]
host_masking = true
host_masking_format = "{token}.users.{network}"
host_masking_token_bytes = 4

Real IPs and hostnames stay off the wire. An oper, or the user themselves, still sees the real address via WHOIS.

bans

KLINE, GLINE and ZLINE take an IP mask and an optional duration (1d, 12h, 30m; permanent if omitted). Set [security] klines_file to persist them across REHASH and restarts. See the protection bundle for DNSBL, the proxy scanner, connect-flood limits and monitoring.
